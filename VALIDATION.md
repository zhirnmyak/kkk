## Проверка внешних сервисов

С текущей конфигурацией из папки поставки на Windows успешно выполнены:

- `GET /me` в MAX: токен принят;
- запрос каталога моделей провайдера: API-ключ принят, выбранная `gpt-4.1-mini` есть в списке.

Результат: [services-host-check.json](services-host-check.json).
Платные запросы генерации, отправка сообщений и второй long polling не запускались.
Эта проверка не подтверждает остаток баланса провайдера или ответы модели на учебные задания.

На этом компьютере у Docker Desktop обнаружен недоступный системный HTTPS-прокси
`127.0.0.1:10808`. Docker сообщил `connection refused` при обращении к registry;
HTTPS-запросы из контейнера к MAX и registry завершились `UNEXPECTED_EOF_WHILE_READING`.
Поэтому онлайн-работа бота **из контейнера на этом Docker-хосте пока не подтверждена**.
Результат этой отдельной сетевой проверки: [services-check.json](services-check.json).

Прокси Docker Desktop не записан в образ. Для запуска на этом компьютере нужно
восстановить локальный прокси либо выбрать доступное прямое подключение в настройках
Docker Desktop → Resources → Proxies. На другом компьютере используются его сетевые настройки.

После восстановления доступа можно повторить только сетевую проверку:

```sh
python scripts/check-services.py maxiimka:hackathon-2026
```

## Как повторить проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -t .
python scripts/verify-container.py maxiimka:hackathon-2026
```

Проверка контейнера создаёт отдельный временный экземпляр с `MAX_BOT_ENABLED=0`
и `LLM_MOCK=1`, после проверки удаляет его. Поиск и OCR проверяются настоящими моделями.
Рабочие документы автора, история бота и его текущий процесс не используются.
