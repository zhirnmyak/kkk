# Мини-приложение МаксИИмки

Для хакатона панель работает локально на компьютере с ботом. Она показывает
настоящие материалы и меняет настройки работающего процесса. Туннель,
публикация сайта и настройка HTTPS для этого режима не нужны.

## Запуск

Подготовь Python-окружение и подключение по [README](../README.md#запуск).
Для сборки интерфейса нужен Node.js 20.19+ с npm.

```powershell
.\start-miniapp-local.cmd
```

Скрипт установит зависимости интерфейса, если их ещё нет, соберёт React-приложение,
запустит терминал, MAX-бота и HTTP-панель. Отдельно запускать `main.py` не нужно:
двум процессам с одним токеном нельзя одновременно получать обновления.

При первом интерактивном запуске появится запрос **ID администратора MAX**.
Это числовой ID пользователя, а не токен или имя бота. Его показывает команда
`/id` или `/айди` в чате с ботом. Если бот ещё не запущен и ID неизвестен,
нажми Enter, узнай ID у работающего бота и укажи его при следующем запуске.

ID сохраняется в `DATA_DIR/admin.json`. Для явного выбора или смены администратора
задай `MAX_ADMIN_ID` в окружении или `.env`; эта переменная имеет приоритет.
Запуск службы или сценария не читает stdin ради запроса ID.

Терминал напечатает ссылку следующего вида:

```text
http://127.0.0.1:8000/app/#LocalToken=<случайный ключ>
```

Открой **всю ссылку** в браузере на этом компьютере. Ключ удаляется из адресной
строки и сохраняется в текущей вкладке. Обновление страницы сохраняет вход;
новая вкладка требует исходную ссылку. Ключ действует восемь часов или до
перезапуска сервера. Для смены порта задай `HTTP_PORT`.

Локальная ссылка даёт права администратора даже при пропуске ID MAX. В этом
случае основными материалами будут файлы пользователя консоли. Отправка
учебных заданий в MAX доступна после указания своего ID и подключения бота.

Остановка — `/выход` в терминале или `Ctrl+C`. Панель прекращает отвечать
вместе с процессом. Чтобы работать с локальными файлами без подключения к MAX,
задай `MAX_BOT_ENABLED=0`; обращения к настроенной модели всё ещё требуют
её доступности.

## Короткий сценарий показа

1. Запусти `start-miniapp-local.cmd` и открой ссылку из терминала.
2. В терминале введи `/файл test-material/kletka.txt` и дождись обработки.
3. Нажми «Обновить материалы». Если задан ID MAX, в поле «Чьи материалы» выбери «Консоль».
4. Открой материал и нажми «Читать весь текст».
5. Перейди в «Настройки», измени нужный параметр и нажми «Сохранить».
6. Обнови страницу: материалы и сохранённые параметры останутся.

Можно также отправить файл боту в MAX. В панели он будет доступен под ID
отправителя; администратор выбирает пользователя в списке. Задания
«Создать тест», «Конспект» и «Карточки» работают с собственными материалами
пользователя MAX и возвращают результат в его личный чат. При просмотре
чужих материалов эти кнопки скрыты.

## Возможности

- Материалы: список, поиск по названию, фильтры PDF/PPTX/TXT, статус обработки.
- Просмотр извлечённого текста с номерами страниц и фрагментов.
- Удаление с подтверждением; также удаляются связанные задания и результаты.
- Администрирование материалов разных пользователей, включая консоль.
- Настройки API: провайдер, адрес, ключ, проверка подключения.
- Модель: название, список доступных моделей, effort, контекст, проверка возможностей.
- OCR: включение, движок, параллельность страниц, проверка Vision.
- Qoder: параллельность запросов, таймаут и вид окна шлюза.
- Терминал: показ размышлений и индикатор ожидания.

API-ключ можно заменить или удалить; уже сохранённое значение клиенту не выдаётся.
Панель и `/настройки` в терминале используют `data/settings.json` в папке проекта.
Несохранённые изменения требуют подтверждения при выходе из раздела;
при конфликте с изменениями из другого окна нужно обновить форму.

Исходные PDF и презентации бот не архивирует: панель показывает извлечённый
текст, а оригиналы следует сохранять отдельно. В просмотре показываются
первые 200 фрагментов большого документа. Загрузка выполняется через чат
или команду `/файл` в терминале.

## Дизайн и демонстрация

Дизайн основан на **Stageshow 1.1.1**. Копия скилла —
[webapp/STAGESHOW.md](../webapp/STAGESHOW.md), описание адаптации —
[webapp/DESIGN.md](../webapp/DESIGN.md), результаты —
[webapp/REHEARSAL.md](../webapp/REHEARSAL.md). Кнопки перехода в чат в панели нет.

Параметр `/app/?demo=1` включает явно помеченный макет с примерными данными.
Он не обращается к API и не сохраняет изменения в рабочем боте. Для настоящих
данных используй ссылку с локальным ключом. `/app/?design=1` — отдельная
статичная иллюстрация Stageshow для проверки композиции.

## Подключение внутри MAX в будущем

Локальный режим открывает панель в браузере компьютера. Встроенная кнопка MAX
около поля ввода в этом варианте не активирована. MAX открывает веб-страницу
мини-приложения, но не размещает её код на своих серверах: для подключения
внутри мессенджера нужен доступный HTTPS-адрес приложения.

Код интеграции уже подготовлен: SDK MAX, проверка подписанного `initData`,
определение роли по ID на сервере и inline-кнопка `open_app`. У кнопки
`web_app` содержит имя бота, а `payload` — параметр запуска; URL в неё не передаётся.
`MAX_WEBAPP_BOT` оставлен пустым, чтобы при локальном показе эта кнопка была скрыта.

Встроенная кнопка «Открыть» настраивается отдельно в **MAX для бизнеса →
Чат-боты → нужный бот → ⋮ → Настройки → URL мини-приложения → вид кнопки
«Открыть» → Сохранить**. Публичного метода Bot API для этой настройки в
использованной документации нет; команды `/me/commands` её не заменяют.
Сам бот может и дальше работать через polling.

Авторизация проверяется сервером: HMAC, возраст подписи и ID пользователя.
`initDataUnsafe` не используется как подтверждение прав. Локальная авторизация
включается только явно, принимает запросы с этого компьютера и отклоняет
чужой Origin и заголовки перенаправления. Настоящий вход внутри клиента MAX
нужно проверить после подключения HTTPS; локальные проверки его не заменяют.

Источники: [локальная документация Bot API](../max-api-docs/README.md),
[введение в мини-приложения](https://dev.max.ru/docs/webapps/introduction),
[MAX Bridge](https://dev.max.ru/docs/webapps/bridge),
[проверка данных входа](https://dev.max.ru/docs/webapps/validation).
