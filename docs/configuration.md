# Настройки МаксИИмки

[Вернуться к README](../README.md)

## Откуда берутся настройки

| Способ запуска | Источник настроек |
| --- | --- |
| `python main.py` | Окружение, `.env`, затем общий сохранённый профиль |
| `start-terminal.cmd` или `python debug_console.py` | Те же настройки; доступны терминал и HTTP-сервер |
| `start-miniapp-local.cmd` | Те же настройки плюс локальная ссылка администратора и сборка интерфейса |

Переменная, заданная в окружении процесса, имеет приоритет перед `.env`.
Общий профиль хранится в `data/settings.json` в папке проекта и содержит в том
числе API-ключ. Он переопределяет подключение, модель и OCR во всех способах запуска.
Панель и терминал изменяют один профиль; сохранение применяется к работающему
процессу. При изменении профиля из другого окна панель просит обновить форму.

`DATA_DIR` меняет папку базы и индекса, но не переносит файл профиля консоли.
ID администратора хранится отдельно в `DATA_DIR/admin.json`; переменная
`MAX_ADMIN_ID` имеет приоритет. Не добавляй `.env`, `max_token.txt` и `data/` в репозиторий.

## Локальное мини-приложение

Запуск: `start-miniapp-local.cmd`. Интерфейс собирается в `webapp/dist` и
обслуживается тем же HTTP-сервером по `/app/`. По умолчанию порт — 8000.
Скрипт включает `MAX_LOCAL_MINIAPP=1`, принудительно ограничивает сервер
адресом `127.0.0.1` и печатает случайную ссылку администратора. Туннель не нужен.

| Переменная | Назначение |
| --- | --- |
| `MAX_ADMIN_ID` | Положительный числовой ID администратора MAX; при отсутствии запрашивается в терминале |
| `MAX_LOCAL_MINIAPP` | По умолчанию `0`; `1` включает локальную авторизацию на время процесса |
| `MAX_WEBAPP_BOT` | Имя бота без `@`; пустое значение скрывает inline-кнопку мини-приложения |
| `MAX_INIT_DATA_TTL` | Максимальный возраст подписанного входа из MAX; по умолчанию 3600 секунд |

Локальный ключ действует восемь часов или до остановки сервера. Он даёт
администратору доступ к материалам и настройкам на этом компьютере.
Сохранённые ключи провайдеров через API не выдаются. Учебные действия с
отправкой в MAX требуют указанного ID администратора и подключённого бота.
Подробнее: [режимы входа и сценарий показа](miniapp.md).

## Подключение к модели

| Переменная | Назначение |
| --- | --- |
| `LLM_PROVIDER` | `openai` для OpenAI-совместимого API или `qoder` для локального шлюза |
| `LLM_BASE_URL` | Базовый адрес API, обычно с окончанием `/v1` |
| `LLM_API_KEY` | Ключ провайдера |
| `LLM_MODEL` | Название доступной у провайдера модели |
| `LLM_REASONING_EFFORT` | Уровень рассуждений, если модель поддерживает этот параметр; `auto` — без явного выбора |
| `LLM_CONTEXT_WINDOW` | Окно контекста для шлюза Qoder; `0` — не задавать |

В консоли команда `/настройки` открывает экран подключения. Стрелки меняют строку
и значение, Enter открывает ввод адреса, ключа или модели, Esc сохраняет профиль
и закрывает экран. В самом MAX эта команда только показывает параметры.

Доступные проверки:

- «Загрузить модели» получает список с `/models`, если провайдер поддерживает этот запрос.
- «Тест подключения» отправляет короткий запрос выбранной модели.
- «Проверить Vision для OCR» проверяет работу с изображением.
- «Перепроверить модель» обновляет сведения о поддержке изображений и рассуждений.

Проверки идут в фоне. Клавиша C, в том числе русская С, отменяет ожидание.
Сведения о возможностях модели кэшируются на 7 дней в `model-capabilities.json`
внутри `DATA_DIR`. Кэш привязан к адресу API, ключу и модели через отпечаток;
сам ключ в нём не записывается.

## Распознавание и поиск

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `OCR_ENABLED` | `1` | Распознавать изображения и сканы |
| `TRANSCRIBE_BACKEND` | `easyocr` | Способ распознавания |
| `OCR_WORKERS` | `3` | Число параллельно обрабатываемых страниц; `0` — без этого ограничения |
| `OCR_FALLBACK_EASYOCR` | `1` | Перейти на локальное распознавание при лимите LLM-OCR |
| `VISION_BASE_URL`, `VISION_API_KEY`, `VISION_MODEL` | Наследуют `LLM_*`, если пусты | Подключение для отдельного режима Vision |
| `EMBED_MODEL` | `intfloat/multilingual-e5-small` | Модель поиска по смыслу |

Варианты `TRANSCRIBE_BACKEND`:

- `easyocr` — локальное распознавание. Веса скачиваются при первом использовании.
- `llm` — распознавание выбранной языковой моделью. Она должна уметь принимать изображения.
- `vision` — отдельный путь через нативный `/ai/run` Workers AI. Настраивается через `VISION_*`; это не универсальный режим для любого API. Изображения перед отправкой преобразуются в JPEG.

В экране настроек консоли и панели доступны `easyocr` и `llm`. При выключенном OCR
текстовые PDF, TXT и текст из PPTX продолжают обрабатываться. Фото и сканы,
из которых нельзя извлечь текст, получают сообщение о выключенном распознавании.

Номера страниц PDF и слайдов PPTX сохраняются. Нечитаемая страница PDF остаётся
заглушкой, чтобы последующие страницы не сдвигались. PPTX с количеством слайдов
больше 15 отклоняется целиком. Сложная композиция слайда не рендерится;
для неё лучше использовать PDF или изображение.

Индекс разделяется по пользователям. После смены модели эмбеддингов материалы
нужно переиндексировать: предварительно сохранить исходники, выполнить `/очистить`
и загрузить их заново. Очистка также удаляет связанные задания и результаты.

## Вложения и вставленный текст

Для MAX обычный файл ограничен `MAX_DOWNLOAD_MB`, по умолчанию 50 МБ.
Для обычных вложений Telegram в приложении установлен отдельный лимит 5 МБ.
ZIP имеет отдельные ограничения: 150 МБ на архив, 200 поддерживаемых файлов,
50 МБ на файл внутри и 300 МБ суммарно после распаковки. Фактическая доступность
скачивания также зависит от мессенджера.

Сообщение от 600 символов, которое не заканчивается знаком вопроса,
считается вставленным конспектом. В режиме `/загрузить` порог снижается до более
200 символов; короткий вопрос остаётся вопросом. Части одной вставки, пришедшие
в течение 3 минут, объединяются. Режим загрузки действует 10 минут.

Удаление документа убирает связанные с ним карточки, тесты и результаты.
У старых записей без привязки к документу источник нельзя определить надёжно;
они удаляются при полной очистке материалов.

## MAX и Telegram

| Переменная | Назначение |
| --- | --- |
| `MESSENGER` | `max` или `tg` |
| `MAX_TOKEN_FILE` | Файл токена MAX; по умолчанию `max_token.txt` в папке проекта |
| `MAX_BOT_TOKEN` | Токен MAX из окружения; если задан, имеет приоритет перед файлом |
| `MAX_POLL_TIMEOUT` | Ожидание обновлений MAX в секундах; по умолчанию 30 |
| `MAX_BOT_ENABLED` | `0` выключает MAX-бота и его напоминания в `main.py` и консоли; HTTP-панель остаётся доступна |
| `TG_BOT_TOKEN` | Токен Telegram-бота |
| `TG_API` | Базовый адрес Telegram Bot API или своего ретранслятора |
| `TG_PROXY` | Явно заданный прокси для Telegram |
| `TG_POLL_TIMEOUT`, `TG_FILE_TIMEOUT` | Таймауты Telegram: по умолчанию 30 и 240 секунд |

Для Telegram укажи `MESSENGER=tg`, задай `TG_BOT_TOKEN` и запусти `main.py`.
Консоль автоматически поднимает фоновый бот только для MAX.
Пример ретранслятора Telegram находится в [deploy/tg_relay_worker.js](../deploy/tg_relay_worker.js).

При запуске `config.py` убирает системные переменные `HTTP_PROXY`, `HTTPS_PROXY`
и `ALL_PROXY`. Прокси для поддерживаемых подключений задаются явно: `TG_PROXY`
и `VISION_PROXY`.

Дополнительные сертификаты MAX лежат в [certs/](../certs/). Клиент добавляет их
к стандартному набору доверенных сертификатов. Путь можно изменить через `MAX_CA_DIR`.

## Polling и webhook

`UPDATES_MODE=polling` — обычный запуск: приложение само забирает обновления.
Позиция чтения сохраняется в `DATA_DIR`, отдельно для MAX и Telegram.

Для webhook укажи:

```dotenv
UPDATES_MODE=webhook
WEBHOOK_SECRET=your-random-secret
HTTP_HOST=127.0.0.1
HTTP_PORT=8000
```

Нужен публичный HTTPS-адрес, который проксирует запросы на `POST /webhook`.
Подписка на webhook на стороне мессенджера настраивается отдельно. Сам запуск
`main.py` её не создаёт. В подписке должен быть указан тот же секрет.

| Мессенджер | Заголовок секрета |
| --- | --- |
| MAX | `X-Max-Bot-Api-Secret` |
| Telegram | `X-Telegram-Bot-Api-Secret-Token` |

В режиме polling маршрут `/webhook` возвращает 404. В режиме webhook пустой
или неверный секрет даёт 403, некорректный JSON — 400.
Маршрут `GET /health` проверяет только доступность HTTP-приложения.

## Хранение и напоминания

`DATA_DIR` по умолчанию указывает на `data/` в папке проекта. Там находятся
SQLite-база `tutor.db`, индекс `chroma/`, кэши и позиции получения сообщений.
Для переноса учебных данных останови приложение и скопируй всю папку.

Напоминания запускаются в 19:00 по часовому поясу машины, где работает бот.
Время задано константой `REMINDER_HOUR` в [config.py](../config.py).
Планировщик включается в `main.py` и при запуске фонового MAX-бота из консоли.
Закрытое приложение напоминания не отправляет. Пользователь консоли их не получает.

## Локальный шлюз Qoder

Это дополнительный вариант подключения. Нужны Node.js и установленный,
настроенный Qoder CLI. Путь к CLI задаётся через `QODER_CLI_PATH`.

```powershell
.\start-terminal.cmd qwen
.\start-terminal.cmd deepseek
```

Аргумент явно выбирает Qoder и одну из предусмотренных моделей. Доступность
модели зависит от подключённого сервиса. При выборе Qoder консоль и `main.py`
запускают шлюз и останавливают свой процесс при выходе. Базовый адрес обычно
`http://127.0.0.1:8787/v1`; вид окна определяется сохранённой настройкой.

При `LLM_PROVIDER=openai` автоматический запуск шлюза отключён, в том числе
для OpenAI-совместимого сервера на localhost. При этом провайдере нужный
API должен быть доступен заранее.

Команда `/картинка <описание>` экспериментальная, по умолчанию выключена.
Её можно включить через `IMAGE_ENABLED=1` при настроенном бэкенде генерации:
`gateway` или `cloudflare` в `IMAGE_BACKEND`.

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| `ModuleNotFoundError` при запуске | Запускается ли Python из `.venv`; установлены ли зависимости из `requirements.txt` |
| MAX отвечает 401 | Правильный ли токен в `max_token.txt` или `MAX_BOT_TOKEN` |
| Конфликт получения обновлений | Не запущены ли одновременно консоль и `main.py` с одним токеном; нет ли активной webhook-подписки при polling |
| Первая загрузка долго обрабатывается | Загружаются ли веса моделей поиска и OCR; есть ли доступ к сети |
| После запуска из консоли другая модель | Проверь профиль `data/settings.json`; он загружается поверх исходных настроек |
| API вернул лимит или отказ в доступе | Проверь ключ, доступность модели и ограничения провайдера |
| Фото не принимается | Включён ли OCR, выбран ли подходящий движок и достаточно ли чёткий снимок |

`LLM_MOCK=1` и `EMBED_MOCK=1` предназначены для проверок без настоящей модели
и смыслового поиска. Автотесты сами включают эти режимы и создают временную базу.
Для ручных экспериментов используй отдельный `DATA_DIR`; при работе в консоли
дополнительно задай `MAX_BOT_ENABLED=0`, чтобы не поднимать фонового бота.
